# 測試 Web UI 運作：從 Selenium 到 AI 原生代理的典範轉移

## 一、引言——為什麼這個主題至關重要

在當今數位經濟中，Web 應用程式已成為企業與用戶互動的主要介面——從銀行交易、電子商務購物到醫療掛號，無一不依賴瀏覽器中的流暢體驗。而在這背後，Web UI 測試扮演著無聲卻關鍵的守門員角色：它確保每一次程式碼變更都不會破壞用戶體驗，確保每一個按鈕、表單和導覽流程都如預期運作。

然而，這個領域正在經歷一場前所未有的深層變革。過去二十年，Selenium 作為 Web 自動化測試的霸主，幾乎是品質保證（QA）工程師的代名詞。但到了 2025-2026 年，情勢已徹底改變：Microsoft 的 Playwright 以 45.1% 的採用率超越 Selenium 的 22%，成為主流框架；生成式 AI 正在從「輔助工具」進化為「自主測試代理」；89% 的組織已在試點或部署 AI 增強的測試工作流程。

這不僅是工具替換，而是測試哲學、團隊技能結構、市場格局與品質文化的全面重構。對於技術決策者、QA 工程師和軟體開發者而言，理解這場典範轉移的內在邏輯、數據支撐和未來走向，已從「選配知識」變為「生存必備」。

本文基於 2025-2026 年最新公開資料——包括 World Quality Report 2025、Katalon State of Software Quality Report、Gartner Magic Quadrant、TestGuild 調查等權威來源——進行全面分析，揭示 Web UI 測試的關鍵趨勢、核心數據、行業觀點、潛在風險，並提出可執行的策略建議。

## 二、主要發現

### 發現一：AI 已從「未來選項」變成「當下現實」

根據 Capgemini/Sogeti/OpenText 發布的 World Quality Report 2025，89% 的受訪組織已在試點或部署生成式 AI 增強的測試工作流程。其中 37% 已在生產環境中使用，52% 處於試點階段。Katalon 2025 年調查（涵蓋 1,500+ 專業人士）進一步顯示：61% 的企業 QA 團隊已全面採用 AI 測試工具，82% 的 QA 專業人士認為 AI 協作與智慧測試是核心未來技能。

市場數據也驗證了這股浪潮。AI 測試自動化市場從 2025 年的 88.1 億美元預計增長至 2032 年的 359.6 億美元，年複合成長率（CAGR）高達 22.3%——遠超整體軟體測試市場的 7.2%。

### 發現二：Playwright 完成歷史性的「霸權更替」

2025-2026 年的框架採用數據呈現出清晰的贏家通吃格局。根據 TestDino 2025 和 TestGuild 2026 調查：

- **Cypress**：採用率約 14%，穩固於前端/元件測試利基市場

Amazon、Microsoft、Apple、Walmart、NVIDIA 等頂級科技企業已全面轉向 Playwright。這標誌著 Selenium 自 2004 年以來長達二十年的統治地位正式終結。

CISQ 2022 年數據顯示，美國軟體品質不佳的年度成本高達 2.41 兆美元，約佔 GDP 的 10%，其中 1.52 兆美元為累積技術債。2025 Quality Transformation Report 進一步指出，40% 的組織表示軟體品質不佳每年造成超過 100 萬美元的損失。

## 三、核心趨勢分析

### 3.1 從「測試自動化」到「AI 原生測試代理」：一場本質轉變

過去的測試自動化，本質上是「讓測試人員寫更少的程式碼」——透過框架和工具減少重複性工作。但 2025-2026 年的趨勢顯示，我們正在進入「AI 原生測試代理」時代：AI 不再只是輔助生成測試程式碼，而是能自主規劃、執行、診斷並修復測試。

最具代表性的里程碑是 Playwright MCP（Model Context Protocol）伺服器。自 2025 年 3 月發布後，它迅速成為最受歡迎的 MCP 伺服器之一，GitHub 星數超過 32,000，週下載量超過 200 萬次。MCP 作為 AI 代理與測試工具之間的標準化通訊協定，讓 AI 模型能直接操控瀏覽器執行測試——這在過去需要複雜的自訂整合才能實現。

更深層的變革來自 Playwright 1.60 版本引入的 AI 測試代理（Test Agents）。Planner 代理能自主規劃測試策略，Generator 代理能自動生成測試程式碼，Healer 代理則能在測試失敗時自動診斷原因並修復。自我修復能力直接回應了測試自動化最痛的瓶頸——維護成本。這解釋了為什麼 AI 測試自動化市場能以 22.3% 的 CAGR 增長：它不是讓測試「跑得更快」，而是讓測試「活得更好」。

然而，行業觀察者發出了清醒的警告。TestGuild 創辦人 Joe Colantonio 在 25+ 年 QA 經驗和訪問 580+ 自動化專家後直言：「大多數『AI 測試工具』只是 GPT 包裝器。」真正的 AI 測試需要深度整合——理解應用程式架構、測試資料、CI/CD 管道和業務邏輯——而非簡單地在表層疊加 LLM 介面。

### 3.2 框架之爭的深層邏輯：為什麼 Playwright 贏了？

Playwright 的崛起不是偶然。它代表了 Web 測試工具設計哲學的根本轉變：

**第一，開發者體驗優先。** Playwright 的自動等待（auto-wait）機制消除了 Web 應用中最大的不穩定來源——時序問題。傳統 Selenium 需要測試人員手動處理頁面載入、元素出現等時序依賴，而 Playwright 內建了智慧等待邏輯。這不僅減少了 flaky tests，也大幅降低了編寫測試的認知負擔。

**第二，多瀏覽器支援的「無痛化」。** Playwright 的 API 在 Chromium、Firefox 和 WebKit 之間完全一致，測試人員不需要為不同瀏覽器維護不同的程式碼路徑。相較之下，Selenium 的瀏覽器驅動程式管理長期是維噩夢——直到 2022 年 Selenium 4.6 引入 Selenium Manager 才緩解此問題。

**第三，網路攔截與行動模擬的內建支援。** Playwright 能攔截和修改網路請求、模擬行動裝置、測試 API 回應——這些功能在 Selenium 中需要依賴第三方工具整合。現代 Web 應用的複雜性使得這些能力從「加分項」變為「必備項」。

**第四，頂級企業的「背書效應」。** Amazon、Microsoft、Apple、Walmart、NVIDIA 等科技巨頭的採用，向市場釋放了強烈信號。這種網路效應自我強化：更多企業採用 → 更多教學資源和社群支援 → 更多開發者具備 Playwright 技能 → 更多企業願意投資 Playwright。

值得注意的是，Selenium 並未消亡。它的 W3C WebDriver 協議標準地位使其在特定場景（如需要多語言綁定的企業環境）仍有不可替代的價值。但從市場份額趨勢來看，Playwright 的主導地位在短期內難以撼動。

### 3.3 AI 滲透的「雙面性」：樂觀數據背後的治理焦慮

89% 的滲透率與 22.3% 的市場 CAGR 描繪了一幅樂觀的 AI 採用圖景。但深入挖掘數據，會發現一個關鍵的結構性矛盾：

- 僅 6% 的工程領導者認為 AI 工具顯著提高了開發者生產力（MIT 2025 年研究）
- 2025 年企業放棄大部分 AI 專案（未達生產階段）的比例從 17% 升至 42%
- Gartner 預測 40% 的 agentic AI 專案將失敗

這些數據指向一個核心問題：**AI 測試的技術成熟度與組織的準備度之間存在巨大鴻溝。** 許多組織急於「上車」AI 測試，卻缺乏清晰的治理框架、ROI 衡量標準和技能培訓體系。

Capgemini 全球品質工程與測試負責人 Mark Buenen 精準點出了這項挑戰：「2025 年我們看到更多對治理、ROI 和跨職能影響的關注。當前的挑戰是縮小 Gen AI 鴻溝，將投資轉化為可衡量的價值。」

此外，AI 幻覺（hallucination）問題不容忽視。AI 生成的測試可能看起來合理，但實際上是錯誤的——這在 2025 年的企業採用中已成為門檻，AI 幻覺率 5-10% 讓許多組織對完全自主的 AI 測試持保留態度。

### 3.4 Flaky Tests：自動化普及後的新「公敵」

當自動化測試的覆蓋率提升，一個隱藏的危機也隨之浮現：不穩定的測試（flaky tests）。2025 年的實證研究顯示，56% 的軟體從業人員頻繁遇到 flaky tests。這不只是技術問題，更是信任問題——當測試結果不可信賴時，團隊會開始忽視測試失敗，最終導致真實缺陷漏到生產環境。

Flaky tests 的根源通常包括：競態條件、硬編碼等待、測試間共享狀態、DOM 渲染延遲。Playwright 的自動等待機制解決了部分問題，但無法根治——因為許多 flaky tests 源於測試設計本身，而非工具限制。

Google 的數據揭示了問題的嚴重性：84% 的 CI 訊號被 flaky tests 扭曲。這意味著開發者在大部分情況下無法確信「測試通過」是否代表「軟體正確」。Atlassian 每年損失 150,000 開發者工時——相當於 72 名全職工程師一年的工作量——僅用於處理 flaky tests。

### 3.5 市場增長的分層結構：誰在引領？誰在跟隨？

2025 年的市場數據揭示了清晰的「增長分層結構」：

| 市場區隔 | 2025 規模 | 預測規模 | CAGR |
|----------|-----------|----------|------|
| 整體軟體測試 | 600 億美元 | 1,125 億美元（2034） | 7.2% |
| 自動化測試 | 354 億美元 | 1,325 億美元（2035） | 14% |

AI 測試自動化以 22.3% 的增速領跑，說明 AI 是整個測試產業增長的核心引擎。視覺回歸測試的 20.8% 增速則反映了現代 Web 應用對 UI 一致性的高度重視——使用自動化視覺回歸測試的組織，UI 相關缺陷漏到生產環境的比率減少高達 78%，QA 週期時間縮短 65%。可訪問性測試的穩健增長由合規壓力（如 ADA、WCAG、歐洲無障礙法案）和社會意識提升共同驅動，Playwright 1.60 已直接內建可訪問性驗證功能，顯示主流框架已將其視為「一等公民」。

## 四、未來展望

### 4.1 短期（2025-2027）：AI 工具從「包裝」走向「深度整合」

未來兩年，市場將經歷一場殘酷的淘汰賽。那些僅在表層疊加 LLM 的「GPT 包裝器」工具將被市場淘汰，而真正深度整合 AI 能力的平台——具備自主規劃、自我修復、智慧測試選擇能力——將脫穎而出。

Gartner 在 2025 年 10 月發布的首個「AI-Augmented Software Testing Tools」Magic Quadrant 已為此定調。Tricentis、UiPath、Keysight 獲評為領導者，這些廠商共同的特點是：AI 能力已深度嵌入測試生命週期的每個環節，而非作為附加功能。

Playwright 生態系統將繼續主導 Web UI 測試。其 MCP 伺服器的快速普及（週 200 萬次下載）預示著 AI 代理與測試工具之間將形成標準化的互動模式，這將進一步鞏固 Playwright 的生態位。

### 4.2 中期（2027-2030）：Agentic AI 的「兌現」或「幻滅」

Gartner 預測 40% 的 agentic AI 專案將失敗——這是一個清醒的警告。Agentic AI（自主代理）的承諾是：AI 能獨立規劃測試策略、執行測試、診斷失敗原因並修復問題。但在 2025 年，這項技術仍處於早期階段，AI 幻覺率 5-10% 使其無法完全自主運作。

未來三年的關鍵看點是：AI 的可靠性是否能突破「生產可用」的門檻。如果 AI 幻覺率能降至 1% 以下，Agentic AI 將真正兌現其承諾；否則，市場將進入「AI 幻滅期」，企業轉向更保守的「AI 輔助人類決策」模式。

Angie Jones 的觀點在此具有指導意義：「無論 AI 多先進，仍需為重要決策保留人類判斷層。」AI 可以處理重複性任務，但測試的『why』和『what matters』需要人類理解。AI 支援測試中的問責制——當 AI 犯錯時誰來負責——將成為組織治理的核心議題。

### 4.3 長期（2030+）：品質工程的「民主化」與「永續化」

長期來看，兩個趨勢將重塑品質工程的格局：

**第一，品質工程的民主化。** 自然語言生成測試（如 Testsigma、ACCELQ、TestDriver.ai）將使非技術背景的團隊成員——業務分析師、產品經理、設計師——能直接參與測試創作。這將打破 QA 的專業壁壘，讓品質成為整個產品團隊的共同責任。

**第二，軟體永續性成為品質指標。** Gartner 預測到 2027 年，30% 的全球大型企業將把軟體永續性列為非功能性需求。這意味著測試將不僅關注「功能是否正確」，還要關注「效能是否高效」、「資源消耗是否合理」、「碳排放是否達標」。這將催生全新的測試類別和工具生態。

## 五、結論與建議

### 5.1 核心結論

Web UI 測試正經歷一場從工具、方法論到人才結構的全面典範轉移。「AI 輔助 + Playwright 為主」的新格局已基本確立，但這並不意味著自動化的「烏托邦」已經到來。相反，我們看到的是：**自動化率與期望的落差、AI 可靠性的不確定性、flaky tests 的持續困擾、以及技能缺口的擴大**，這些挑戰正在考驗所有組織的落地能力。

### 5.2 給技術決策者的六項具體建議

**建議一：務實採用 AI，從「小範圍試點」開始**

不要試圖一次性地全面部署 AI 測試。選擇一個業務影響明確、測試基礎較好的應用程式作為試點，設定具體的衡量指標（如測試維護時間減少、缺陷捕獲率提升、CI 執行時間縮短），在 2-3 個月內驗證 ROI 後再決定是否擴大。同時建立 AI 測試的治理框架——包括 AI 生成測試的人類審查流程、錯誤問責機制和幻覺風險管控。

**建議二：投資 Playwright 技能，建立內部卓越中心**

Playwright 已成為市場主流且需求持續增長。建議：
- 對現有 QA 團隊進行 Playwright 系統培訓（建議 40-60 小時的實作訓練）
- 建立 2-3 人的 Playwright 卓越中心，負責制定最佳實踐、維護共用測試框架
- 新專案預設採用 Playwright，僅在特殊需求（如多語言綁定）時考慮 Selenium

**建議三：建立 Flaky Test 治理機制，設定量化目標**

Flaky tests 是侵蝕自動化信任的慢性毒藥。建議：
- 設定「flaky test 率低於 2%」的量化目標
- 建立 flaky test
