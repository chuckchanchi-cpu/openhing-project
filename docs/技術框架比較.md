## 二、各框架深入分析

### 2.1 CrewAI — 角色為本的自主團隊

**推薦指數**: ⭐⭐⭐⭐⭐

#### 核心概念
將多智能體協作建模為團隊（"Crew"），每個 Agent 有角色、背景故事和目標。Agent 之間可以自然溝通、委派任務。

#### 特色功能
- **兩種模式**: Crews（自主團隊）和 Flows（事件驅動管道）
- **三種流程**: 順序（Sequential）、分層（Hierarchical — 自動生成管理員 Agent）、共識（Consensual）
- **無外部依賴**: 不依賴 LangChain 或其他框架
- **A2A 協議支援**: 正在增長
- **100K+ 開發者社群**

#### 程式碼範例
```python
from crewai import Agent, Task, Crew

researcher = Agent(
    role="高級研究分析師",
    goal="準確、全面地搜集主題資訊",
    backstory="你是一位嚴謹的研究員，總是從多個來源核實事實。",
    tools=[search_tool, web_scraper],
)

writer = Agent(
    role="技術寫手",
    goal="將研究結果轉化為清晰、吸引人的內容",
    backstory="你擅長用淺顯易懂的方式解釋複雜技術概念。",
)

crew = Crew(
    agents=[researcher, writer],
    tasks=[research_task, writing_task],
    verbose=True
)

result = crew.kickoff(inputs={"topic": "AI Agent 採用趨勢"})
```

#### 優點
- ✅ **直觀易用** — 角色團隊的思維模型自然，非工程師也能理解
- ✅ **快速原型** — 1 小時內從想法到可運行多 Agent 系統
- ✅ **內建協作** — Agent 自動委派、問答、接力，無需手動實現協調邏輯
- ✅ **最佳預設值** — 重試邏輯、輸出解析、記憶管理開箱即用
- ✅ **CrewAI 推薦** — fring1118 也推薦這個

#### 缺點
- ❌ Token 成本高 — 4 個 Agent 協作比單 Agent 多用 3-5 倍 Token
- ❌ 主要面向任務型工作流，不適合持久性 Agent 社群
- ❌ 進階用例靈活性有限

#### 最佳適用場景
**複雜業務工作流，需要清晰角色分工** — 研究團隊、內容生產線、客服流程

### 2.2 LangGraph — 圖形化狀態機

**推薦指數**: ⭐⭐⭐⭐

#### 核心概念
將應用建模為有向圖，Agent 是節點，邊定義共享狀態的流動。每個 Agent 讀寫中央狀態物件，框架管理狀態持久化和合併更新。

#### 特色功能
- **持久化執行** — Agent 可穿越故障自動恢復
- **Human-in-the-loop** — 可隨時檢查和修改狀態
- **完整記憶系統** — 短期工作記憶 + 長期持久記憶
- **生產級 middleware** — 重試、內容審查、監控（v1.1, 2025.12）
- **LangChain 生態系統** — 大量整合

#### 程式碼範例
```python
from langgraph.graph import StateGraph, END
from typing import TypedDict, List

class ResearchState(TypedDict):
    query: str
    sources: List[str]
    summary: str
    enough_info: bool

def search(state: ResearchState) -> ResearchState:
    results = search_tool(state["query"])
    state["sources"].extend(results)
    return state

def evaluate(state: ResearchState) -> ResearchState:
    state["enough_info"] = len(state["sources"]) >= 3
    return state

def summarize(state: ResearchState) -> ResearchState:
    state["summary"] = llm.summarize(state["sources"])
    return state

graph = StateGraph(ResearchState)
graph.add_node("search", search)
graph.add_node("evaluate", evaluate)
graph.add_node("summarize", summarize)
# ... 定義條件邊和循環邏輯
```

#### 優點
- ✅ **最大控制力** — 每個步驟精確定義，無隱藏邏輯
- ✅ **生產就緒** — 內建持久化、串流、HITL、LangSmith 監控
- ✅ **生態豐富** — 連接所有 LLM 提供商、向量資料庫、工具
- ✅ **Python + JS 支援**

#### 缺點
- ❌ **學習曲線陡峭** — 狀態圖思維模型需要時間內化
- ❌ 簡單用例過於冗長
- ❌ 文檔變化快 — API 經常更新
- ❌ 無原生 A2A/MCP 協議支援

#### 最佳適用場景
**需要容錯和精確狀態管理的生產級 Agent** — 適合已投入 LangChain 生態的團隊

### 2.3 AutoGen → Microsoft Agent Framework (MAF)

**推薦指數**: ⭐⭐⭐ (注意：AutoGen 已進入維護模式)

#### 核心概念
由 Microsoft Research 創建，開創多 Agent 對話模式。Agent 通過結構化對話互動（雙人聊天、群組聊天、序列對話、嵌套對話）。

#### ⚠️ 重要更新（2026年4月）
AutoGen 已進入**維護模式**，Microsoft 推出 **Microsoft Agent Framework (MAF)** 作為企業級繼承者：
- 合併 AutoGen 的 Agent 抽象 + Semantic Kernel 的企業工具
- 特性：型別安全 API、狀態管理、遙測、過濾器、審批工作流
- 圖形化工作流 + 檢查點 + Human-in-the-loop

#### 優點
- ✅ 最多樣的對話模式
- ✅ 巨大的社群（50K+ Stars）
- ✅ 提供無程式碼 Studio 介面
- ✅ .NET 支援

#### 缺點
- ❌ **AutoGen 不再有新功能** — Microsoft 重心轉向 MAF
- ❌ 集中式管理（Group Chat Manager）可能成為瓶頸
- ❌ 協議互通性有限

#### 最佳適用場景
**對話型多 Agent 場景** — 群組決策、辯論、共識建立

---

### 2.4 OpenAgents — 網路型 Agent 社群

**推薦指數**: ⭐⭐⭐

#### 核心概念
建立持久性 Agent 網路 — 自我維持的社群，Agent 可以發現同伴、協作任務、隨時間成長。

#### 特色功能
- 原生 MCP + A2A 協議支援
- 持久性網路（Agent 可隨時加入/離開）
- 視覺化 Studio 介面

#### 最佳適用場景
**需要 Agent 互通性和持久性網路的場景**（較新，生態尚未成熟）

## 四、推薦方案

### 🎯 首選推薦：CrewAI

**適合 Openhing 「研究助手」場景的原因：**

1. **最直觀** — 研究助手 = 1 個研究 Agent + 1 個分析 Agent + 1 個寫作 Agent，角色化定義自然對應
2. **最快上手** — 1 小時內可跑通原型，適合 Openhing 第一週目標
3. **角色為本** — 符合「增強人類」願景，Agent 是協作者而非取代者
4. **fring1118 推薦** — 已確認一致

### 🥈 備選：LangGraph

- 如果後續需要更複雜的工作流控制（條件分支、循環、持久化執行）
- 可從 CrewAI 原型過渡到 LangGraph 生產化

### 🥉 不推薦：AutoGen
- 已進入維護模式，Microsoft 重心轉移至 MAF
- 除非需要 .NET 支援或特定對話模式
